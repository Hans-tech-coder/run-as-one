# Path Traversal in /api/upload via Unsanitized file.name

**ID:** vuln-0008
**Severity:** MEDIUM
**Found:** 2026-09-23 01:56:37 UTC
**Target:** /api/upload
**CVSS:** 4.3
**Confidence:** High
**Fix Effort:** Trivial

## Description

The `/api/upload` endpoint uses `uploadPublicFile` to store images and templates in Vercel Blob. It passes `file.name` directly from the multipart form data without sanitizing directory traversal sequences (like `../`). An authenticated organizer can place files outside the intended `events/` folder in the public Blob store.

## Evidence

In `src/lib/blob.ts`, the function `uploadPublicFile` does not sanitize the uploaded file name:

```typescript title=src/lib/blob.ts startLineNumber=89 endLineNumber=104
export async function uploadPublicFile(
  file: unknown,
  folder: string,
  kind: UploadKind = 'image'
): Promise<string> {
  assertUploadable(file, kind);

  const blob = await put(`${folder}/${file.name}`, file, {
    access: 'public',
    addRandomSuffix: true,
    contentType: file.type,
    token: storeToken('public'),
  });

  return blob.url;
}
```

Since `file.name` is provided by the client, an attacker could supply `../../../malicious.png`, and it would be concatenated into the `put` destination path without stripping the traversal sequence.

## Impact

An attacker with organizer privileges can write files to arbitrary directories within the public Vercel Blob store. This can pollute other directories (like `avatars/`) and bypass intended directory structuring.

## Counterevidence

Vercel Blob uses `addRandomSuffix: true`, preventing existing files from being overwritten by simply guessing their names. Furthermore, files are stored on a separate public Vercel Blob domain which mitigate Cross-Site Scripting (XSS). However, the ability to store files in arbitrary directories via directory traversal sequences is confirmed since the `file.name` is completely unsanitized.

## What Would Change This Severity

If it is found that an attacker can exploit this path traversal to overwrite critical configuration files or executable assets on the blob store (by somehow bypassing the random suffix logic), the severity would increase to High.

## Technical Analysis

The vulnerability resides in `src/lib/blob.ts` where `uploadPublicFile` directly incorporates `file.name` into the blob storage path string:

```typescript
const blob = await put(`${folder}/${file.name}`, file, {
```

Unlike `uploadPrivateProof`, which uses the helper function `proofFileName` to parse the filename and safely derive a base name while appending a trusted extension, `uploadPublicFile` implicitly trusts the client-provided `file.name` property.

By sending a `filename` containing `../`, an authenticated user can perform path traversal, storing the resulting file in arbitrary directories within the public storage bucket. Although Vercel's `addRandomSuffix: true` option mitigates file overwriting, an attacker can still break directory boundaries and upload to any arbitrary path within the store.

## Proof of Concept

1. Authenticate as an organizer with the `event:create` or `event:edit` permission.
2. Send a POST request to `/api/upload` with a multipart form body containing a file.
3. In the `filename` directive of the `Content-Disposition` header for the file part, supply a path traversal string, e.g., `filename="../../../avatars/hacked.png"`.
4. Observe that the returned Blob URL confirms the file was saved into the `avatars` folder instead of the `events` folder.

```python
import requests

# Assuming valid session cookies for an organizer
cookies = {
    'session': 'YOUR_VALID_SESSION_COOKIE_HERE'
}

files = {
    'kind': (None, 'image'),
    'file': ('../../../avatars/hacked.png', b'dummy content', 'image/png')
}

response = requests.post(
    'http://localhost:3000/api/upload',
    cookies=cookies,
    files=files
)

print(response.json())
# Expected output includes a URL pointing to the avatars/ folder in Vercel Blob.
```

## Remediation

Sanitize `file.name` in `uploadPublicFile` by stripping out directory traversal characters (`/` and `\`), just like it is done in `uploadPrivateProof`. Additionally, override the file extension by relying on the explicitly validated Content-Type rather than trusting the user-provided filename.

## Fix Verification

Security Closure: Re-tracing the source -> control -> sink shows that `file.name` will now have any directory paths (like `/` or `\\`) split and popped off, meaning traversing out of the target folder is no longer possible.

Bypass Review: The fix relies on `split(/[\\/]/).pop()`, which is a common and reliable way to strip path components in Javascript. The extension is overridden strictly by the file's Content-Type via `extensionForType(file.type)`, meaning the attacker cannot control the file extension on disk either.

Preserved Behavior: Normal uploads will simply have their directory components (if any) stripped and correctly saved. Tests checking uploads continue passing normally.

Repository Checks: Types and syntax are valid. `extensionForType` is already imported at the top of the file.

## Assumptions

Assumes an attacker with organizer privileges (who can reach the `/api/upload` endpoint) attempts to upload files outside the intended destination directory in the public Blob store.
